# 支付商品、折扣与权益发放方案

## 目标

把当前“充值/订阅收款”扩展成可由后台配置、由服务端结算、由订单幂等发放的商品系统，覆盖：

- 多个订阅套餐与充值档位；
- 固定售价与划线原价形成的套餐折扣；
- 月、季度、年套餐（当前按固定天数履约：30/90/365 天）；
- 购买后自动发放订阅、余额赠送和重置次数；
- 桌面端充值页展示服务端配置，而不是写死商品信息。

## 设计边界

桌面端只读取 `GET /api/v1/payment/checkout-info` 并打开服务端收银页。价格计算、支付回调、优惠校验、库存/次数发放和退款补偿都在服务端完成。任何客户端传入的金额、折扣或权益只作为展示/选择，不作为结算依据。

本阶段采用“套餐静态折扣”：`original_price` 是展示用原价，`price` 是服务端最终售价，订单会保存两者及折扣快照。注册优惠码不复用为支付优惠码；支付优惠券作为后续独立能力设计，避免把注册赠送余额误当成订单折扣。

## 数据模型

### `subscription_plans`

保留现有字段，并增加 `entitlements JSONB NOT NULL DEFAULT '{}'`：

```json
{
  "balance_bonus": 10.0,
  "reset_card_count": 2,
  "reset_card_expiry_days": 90,
  "message": "购买后赠送 2 次额度重置"
}
```

字段约束：

- `balance_bonus >= 0`；
- `reset_card_count` 为 0 到 1000 的整数；
- `reset_card_expiry_days` 在赠送重置次数时必须为正数；
- 只返回公开展示字段，不返回支付 provider 配置或内部审计数据。

`validity_unit` 支持 `day(s)`、`week(s)`、`month(s)`、`quarter(s)`、`year(s)`；季度和年度当前归一化为 90/365 天，不做自动续费。

### `payment_orders`

增加 `product_snapshot JSONB`。创建订阅订单时把套餐名称、原价、售价、币种、折扣金额/比例、有效期和权益完整快照写入订单。后续管理员修改套餐不会改变已付款订单应发放的内容。

### 充值档位

新增设置 `PAYMENT_RECHARGE_OPTIONS`，值为 JSON 数组：

```json
[
  {"amount": 20, "original_price": 20, "label": "体验档", "description": "适合轻量试用", "balance_bonus": 0, "concurrency": 2, "estimated_rate_multiplier": 1, "estimated_tokens": 2000000, "sort_order": 10, "enabled": true},
  {"amount": 100, "original_price": 120, "label": "成长档", "description": "日常使用更划算", "balance_bonus": 8, "concurrency": 5, "estimated_rate_multiplier": 0.9, "estimated_tokens": 12000000, "sort_order": 20, "enabled": true}
]
```

`amount` 是用户实际支付的档位金额，`original_price` 只用于划线原价，折扣百分比由服务端根据两者自动计算，不能由客户端传入。`balance_bonus` 会在全局充值倍率计算后实际增加到账余额；`concurrency` 是支付成功后写入用户并发上限的最低目标，不会降低已有更高上限。`estimated_rate_multiplier` 与 `estimated_tokens` 仅用于按量卡片的参考展示，不参与结算或权益发放。

金额仍受全局及支付渠道 min/max 限制；只要存在启用的充值档位，创建订单的金额必须精确匹配某个启用档位，不能通过接口绕过固定档位。非法或空配置回退为空数组，桌面端再回退兼容档位；支付订单会冻结档位名称、原价、售价、折扣、实际到账金额、估算字段和权益快照。

## 订单与履约

1. `/payment/checkout-info` 返回充值档位、套餐权益和折扣展示数据。
2. 创建订单只接收 `plan_id` 或充值档位金额；服务端重新读取在售套餐/档位并计算最终支付金额与实际到账金额。
3. provider webhook 验签、金额校验通过后进入现有 `PAID -> RECHARGING -> COMPLETED` 租约流程。
4. 履约事务内按 `product_snapshot`：充值订单兑换冻结后的到账金额并发放并发目标，订阅订单延长订阅、赠送余额、赠送重置卡，并分别写入订单审计动作。
5. 每个订单/动作使用已有 `payment_audit_logs(order_id, action)` 唯一约束；重试先查审计再执行，避免重复发放。
6. 履约完成后发送包含赠送余额、重置次数和到期时间的成功通知；通知失败不回滚已完成权益。

## 订阅变更与平台约束

`user_subscriptions` 对未删除记录建立 `(user_id, platform)` 唯一约束。平台从套餐分组固化到订阅记录，历史记录不会因为管理员后来修改分组平台而被重新归类；迁移时保留每个平台优先级最高的一条记录，其余记录软删除并保留审计/重置卡历史。

购买同一平台的套餐时由服务端判断操作类型：

- 当前套餐仍有效且目标分组相同：续费，按目标套餐全价在原到期时间上追加周期；
- 当前记录已到期：重新订阅，周期从支付履约时的当前时间开始，并清空旧的日/周/月用量窗口；不会从旧到期时间继续累加；
- 当前套餐仍有效且目标套餐每日价格更高：升级，按剩余天数收取补差价；降级和未知历史价格的升级不允许直接执行。

升级金额按分为单位向上取整：

`ceil((目标价 / 目标周期天数 - 当前价 / 当前周期天数) * ceil(剩余天数))`。

升级只替换平台、分组和套餐商业条款，保留原到期时间及已使用额度；不重复发放完整周期的余额赠送、重置次数或并发权益，避免补差价订单产生超额权益。续费/重新订阅仍按订单快照发放套餐配置的权益。

## 独立购买重置次数

独立重置次数订单使用 `order_type=subscription_reset`，必须指定一个当前用户仍有效的订阅和购买数量（1 到 100 次）。服务端读取该订阅固化的实际套餐价格，单次价格为 `ceil(当前订阅价 / 3, 分)`，订单金额、平台、分组、数量和有效期全部写入不可变商品快照；客户端金额只用于展示，不能参与结算。

每批独立购买的重置次数从发放时起有效 14 天。支付履约在同一事务中锁定目标订阅、插入批次并写入唯一审计动作，重复回调最多发放一批。订阅已经到期、平台/分组在支付前发生变化，或缺少历史套餐价格时进入错误/人工处理，不会按旧到期时间或客户端价格发放。

## 桌面端契约

`PaymentCheckoutInfo` 新增 `rechargeOptions`；`SubscriptionPlan` 新增 `entitlements`、`discountPercent` 和 `periodLabel`。旧服务端缺少这些字段时，Rust 使用 serde 默认值，页面回退兼容充值档位和空权益，不阻断已有充值/订阅。

桌面端展示：套餐名称、周期、现价/原价/折扣、描述、服务端 features、赠送余额和重置次数；充值档位来自服务端配置。订单创建和二维码仍由服务端页面完成。

## 非目标

- 本阶段不接入自动续费、订阅扣款计划或支付券叠加规则；
- 不把注册 promo code 改造成支付 coupon；
- 不在桌面端保存支付密钥、订单签名或权益发放状态；
- 不改变已有 provider、webhook、退款状态机。

## 验收标准

- 管理员可创建/编辑多个套餐，配置季度/年度周期、原价/售价和权益；
- 结算订单保存商品与权益快照，修改套餐后原订单重试仍发放原权益；
- 同一 webhook、手动重试或并发重试最多发放一次余额和重置卡；
- 充值页显示后台配置档位，旧服务端/非法配置有安全回退；
- 订阅、余额、重置卡和通知相关现有测试全部通过，并新增迁移、校验、契约和履约幂等测试。

## 后续阶段：支付优惠券

另建 `payment_coupons` / `payment_coupon_redemptions`，支持固定金额或百分比、有效期、适用套餐、用户/总次数上限、不可叠加规则。创建订单时锁定 coupon 使用并快照折扣，支付失败/过期释放，支付成功原子核销，退款按明确的返还策略处理。
