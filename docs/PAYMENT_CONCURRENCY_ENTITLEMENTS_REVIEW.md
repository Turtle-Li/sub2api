# 支付并发权益独立审查记录

审查人：Claude Code（只读独立审查）
范围：支付订单快照、履约幂等、认证缓存 outbox、退款和 Ent schema。

## 已采纳并修复

| 风险 | 处理 |
| --- | --- |
| 停售充值档位可通过手输金额继续领取并发 | 仅启用的充值档位可命中订单快照，并加入回归测试。 |
| 低档订单回调晚到会覆盖高并发 | 并发改为原子 `max(current, target)`，同订单审计键保证一次发放。 |
| 认证缓存触发器忽略并发/余额 | 新迁移将 `concurrency`、`balance`、`total_recharged`、`rpm_limit` 纳入事务性 outbox 触发条件。 |
| 缓存失效失败将已履约订单标记为失败 | 提交后的订阅缓存失效改为告警和最终收敛，不再改变订单履约结果。 |
| 新环境可能缺失审计幂等唯一约束 | Ent schema 对齐迁移 131，声明 `(order_id, action)` 唯一索引。 |
| 含并发权益的订单退款后权益残留 | 在可逆权益账本上线前，阻断这类订单的自助和后台自动退款，要求人工审核。 |

## 保留的产品边界

当前并发权益只会提高账户当前值，不会随订阅到期自动降低。要支持到期降级、重叠订阅按最大值、部分退款和可逆回滚，下一阶段必须先引入 `user_entitlement_grants` 权益账本与重算器；不能在 `users.concurrency` 上做减法。
