## 人工交付配置与历史兼容

- `275_shop_delivery_config.sql` 增加 nullable JSONB `shop_products.delivery_config`。
  `{ "individual_copy": true }` 是当前唯一可启用项；未配置或 false 归一为空，DTO
  使用 `omitempty`，旧订单序列化不凭空出现新字段，原生版本零绑定摘要不变。
- 仅人工 `account_delivery` 可启用。代充和任何自动付款动作均在服务端拒绝启用，
  管理界面只在“人工交付 → 成品号”显示默认关闭的“开启逐项复制”。切换到其他
  交付方式会清除开关；不由指南类型、多行文本或分隔符推断此能力。
- 配置随购买商品快照冻结，只影响当时的新订单；改动目录不会修改旧订单。默认
  复制完整原文。显式启用后复用原 `account----password` 解析器分别复制两项，
  其他人工成品号格式可逐行复制。自动 API Key 始终仅完整复制。
- Ent 由 schema 重新生成，不手改生成文件。迁移可重复执行，增加列不重写历史
  快照、密文、财务状态、任务/回执、已购价格或原 paid_at。
