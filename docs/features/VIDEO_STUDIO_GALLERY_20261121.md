## 决策与验收目标

保留独立的 `/video-studio`，与生图工作台共用宿主导航、主题和创作布局；不把视频当作图片任务的一种状态。图片页的「转视频」仍只移交草稿。支持 Muse、H3、H3 Fast；本次不接 SD，不改价格、钱包、公共 API 或生产开关。

上一版的任务索引没有回答「这是哪条作品、当时怎么生成的」。本版以成片帧为入口：无需播放即可在多幅作品间辨认，读到模型、请求秒数和画幅；打开详情核对提交尺寸、素材模式/数量、可选 Seed。未指定的尺寸不猜；授权错误、未核实的回执、旧作品没有帧与参数都不能拿素材、生成图片或当前默认值填补。

## 封面与参数的数据来源

原生 Muse 完成回执给可验证的媒体文件名；H3 的内容入口是已绑定原任务的 `/content`，两者都没有本项目可依赖的原生缩略图契约。不从任意上游 URL 下载图片。仅会话工作台的提交或**单条明确追踪**可收集原适配器校验过的读取方法；在完成回执已持久化后，服务端才尝试生成预览。普通 `/v1/videos` 不启用此路径。H3 直接返回已完成和账务待核实的成片均可处理；Muse 不把提交回执当成首次完成计费观察。关闭页面后才完成、尚无完成观察的任务，列表仍显示本地已知状态，需查询原任务；浏览历史不代用户观察／结算。

- 每次抽帧最多 **一个** 原渠道媒体 GET，无二次状态查询、无生成或账户切换。先尝试前 1 MiB；尾部含视频索引时才在同一流继续读取（上限 24 MiB）。FFmpeg 只接收已解绑路径的本机文件描述符，不接收 URL、认证头或进程凭据；只解码第一幅视频画面，不用嵌入的封面附件。至多两路、每次最多 6 秒；无法解码、超限或高负载时不影响原任务和手动取片。
- 保存的是边长最多 512px、最多 128 KiB 的 JPEG。Redis 使用独立命名空间、原用户/Key/组/任务/回执标识和按提交时间最多 24h 的 TTL；分布式租约防止重复取媒体，无批量回填，无持久化视频文件。缓存丢失允许退化为「暂无封面」。Linux 的三个发布镜像入口显式安装 FFmpeg；独立二进制部署若没有支持 `fd` 输入的 FFmpeg，封面不可用，老的取片路径不受影响。
- 迁移 `283_video_studio_parameters.sql` 为私有历史行添加 **可空** JSONB。只有创建时的 `material_mode`（text、references、first_frame、first_last_frame）、`reference_count` 和指定的 `seed` 被保存。秒数、尺寸继续读原行，不是量测到的成片规格；`seed:0` 是有效值。原图、提示词、原生结果地址、推测的片名均不入库。不更新旧行、不改指纹或幂等占位。

## 会话接口增量

- `GET /api/v1/video-studio/jobs`、`GET …/jobs/:id` 和 `POST …/jobs` 的成功记录可返回 `parameters` 和 `has_poster: true`（同时给出 `poster_expires_at`，即小图可读窗口的上界）。无字段代表「不知／暂无」，不是「零」或「文本生成」。集合只读任务索引和一次批量缓存长度查询，不传 JPEG、原片或私有媒体地址。
- `GET /api/v1/video-studio/jobs/:id/poster` 只读已有 JPEG，绝不在读封面时生成；JWT、本人和原 Key/组、IP、有效性、原回执及绑定账号检查通过才返回 `image/jpeg`、`Cache-Control: private, no-store`、`nosniff`。请求不能选一个别的 Key；不因余额已用完而拒绝已有成片。禁用原 Key、失去分组、归属消失、已过期／不属于本人应拒绝。旧片无封面可手动播放；原媒体权限不因曾有封面而延长。
- `/content` 仍只用于明确播放／下载。查看参数不发单条状态请求。关闭新单时原任务查询、取片和原渠道账务路径继续工作。数据库增量向后兼容，不需回退数据。

生图样式与行为的对照沿用项目已固定的 88lin revision `5523a592af054bfe4cbee76c2ef8d866ce5cd81e`：已查 `TaskGrid.tsx`、`TaskCard.tsx` 和 `useNearViewport.test.tsx`；许可与有意差异见 `frontend/src/features/image-studio/UPSTREAM.md`。视频没有复制其原图/缩略图归属或存储接口。
