## UI / API 实现契约

沿用登录态 `/api/v1/video-studio`，不接收浏览器组 ID、Key ID 或凭据。`/models` 返回已获准且有价格/账户的目录，含已有 seconds/sizes/supports_frames/supports_seed/quotes 等；新增 `reference_kinds: ('image'|'video'|'audio'|'file')[]`、`muse_options?: {resolution_max_bytes:number,extra_max_bytes:number,timeout_max:number,native_size_max_bytes:number}`。目录缺少可选字段时按老目录（仅参考图，不显示额外项）处理。

| 请求项 | Muse | H3 | H3 Fast |
|---|---|---|---|
| 提示词（必填，最多 8192 UTF-8 字节） | 是 | 是 | 是 |
| 创作时的时长设置 | **渠道自动**，不提供时长控件，提交不带 `seconds` | 可选整数 4–15 秒；默认 5 | 可选整数 5–14 秒；默认 5 |
| `size`（已有字段） | 画幅 auto/16:9/9:16/1:1；原生画质与比例是创作意图，不保证成片尺寸 | auto/1344x768/768x1344/768x768/1024x768/768x1024/1536x672 | auto/1344x768/768x1344 |
| 可选 `native_size`、`resolution` | 原生画布意图（最多64字节，和所选画幅互斥）、画质文字意图（最多64字节），非计费分辨率 | — | — |
| 可选 `timeout`、`extra` | 原生任务等待上限1–600秒（留空由渠道决定）、补充描述文本（最多4096字节）；不是网页超时或任意 JSON | — | — |
| 参考（`references: string[]`） | 最多10个、保持顺序：图片/视频/音频/文件(PDF) | 最多10个，图片/视频/音频 | 同 H3 |
| `first_frame`, `last_frame` | 不提供结构化帧参数 | 首帧、可选尾帧；与参考素材互斥 | 同 H3 |
| `seed` | — | — | 可空整数0–2147483647 |

工作台上传使用本地 Base64 data URL（不接收远程地址）。图片 PNG/JPEG/WebP，视频 MP4/WebM，音频 MP3/WAV，文档 PDF；单个 8 MiB，Muse 参考视频由原生渠道验证时长（≤120 秒）；整个 Studio JSON ≤24 MiB，H3 整个请求 ≤8 MiB；保留图片像素保护。素材别名与原生数组不重复画控件。非图片用文件类型/文件名呈现，不当图预览。所有附加字段均是 typed 顶层字段，切模型清掉不支持的值；quote_id 变化重新确认。成片从未保证上游一定满足文字意图。

详情沿用私有 poster/content、显式点击才播/下载，已知且安全时显示实际提交选项。`parameters` 新增可选 `duration_mode`、`reference_kinds`（按提交顺序）、`resolution`、`native_size`、`timeout`、`has_extra`；不保存或虚构提示词、补充文本、原文件名/URL。旧记录缺值明确标注。无占位假封面或假价格。

### Muse 的「渠道自动」与分组钱包的关系

- 固定上游 `muse2api@b60f474977f125210eb7c71b0fc6668b2f1dd700` 的 `app.py:build_video_prompt/create_video` 把 `duration` 写入自然语言指令，未提供保证成片长度的独立开关。已有一笔请求 5 秒、文件实测 10 秒；这不代表所有作品都是 10 秒。
- 工作台目录返回 `duration_mode: automatic | selectable`。仅 Muse 自动：`min_seconds = max_seconds = default_seconds = 6` 是沿用原生默认的**报价基数**，`quotes` 只含这一档。服务端按当前用户、分组及模型重新计算报价，并用 `quote_id` 核对价格与币种快照；Muse 按该档结算，不因成片长于预期而加价。H3 / Fast 的请求范围与报价机制不变，不能省略秒数。
- 新 Muse 提交省略 `seconds`，旧客户端显式传同一默认 6 兼容且幂等；其他自定义秒数不能用于新任务，拒绝在占款和上游请求之前。未改公开 `/v1/videos` API。已存在的旧请求按原指纹找回，不重发、不改历史扣费。
- `parameters.duration_mode` 和旧记录中的 `seconds` 只用于创作兼容与账务。画廊与详情仅展示**该文件的实长**；未知则不显示时长项，不比较请求值，也不将「自动时长」作为作品参数。渠道任务 `timeout` 是单独的等待上限。

参考：Muse 原生 `muse2api@b60f474977f125210eb7c71b0fc6668b2f1dd700` 的 `app.py` (VideoRequest/build_video_prompt)、`tests/test_reference_limits.py`、`tests/test_muse_video_delivery.py`；本地 `muse_media_request.go`、`muse_media_reference.go`。H3 契约按 `docs/goodput-h3-video.md` 及本地 `goodput_video_request.go` 离线核对。限定 MIME/内存及敏感文本不入历史是宿主有意差异。

## 登录身份、授权与结算

- 默认仅发现用户本来就有权使用的标准渠道分组。目录和提交均读取服务器分组、准入账号与报价，不查询用户有没有个人 Key；`request_id` 只在该用户内幂等。`api_key_id=0` 仅代表该用户在该组的工作台账本命名空间，不是密钥，不写 `api_keys`，也不改变 `/v1` 权限。
- 如需像生图一样让没有任何个人分组授权的新用户直接使用：管理员须同时明确指定 `gateway.video_studio_muse_group_id`（或 `video_studio_h3_group_id`）并开启 `video_studio_share_configured_groups`；未指定组永远不共享。H3 还须匹配独立准入 `goodput_video_public_group_id`。受限用户仍须在允许名单中；更换、禁用或撤销原组不能借另一个组读取媒体。仅开启工作台不使私有分组自动公开。以上均默认关/零；此任务不改线上配置。
- 登录用户只选择模型。Muse 未固定组时按管理排序选第一个符合条件的已授权专用 Muse 组；报价绑定用户、原组、模型、币种与秒数价格表，失配拒绝而不是自动换价。继续用原 key/原组认证旧任务；新钱包授权不是历史私钥的替身。关闭创作开关只暂停新提交。
- 复用视频的数据库预留/结算事务；付费前原子检查可用余额并冻结报价，不足不派发。Muse 会话单沿用同一个视频结算实现，但单独的任务表只允许 Muse（迁移 284）；H3 在既有账本保留实测秒数及上限。成功只扣一次，确定失败退款；提交结果不明保留冻结、等待对账，不自动重发。无个人 Key 不制造普通 `usage_logs` 的虚假外键，与生图一致。工作台条目在同一事务写入 `charged_amount` / `charged_currency`，仅实际结算后返回；未知不显示为零，不按当前报价倒推历史价格。背景对账通过原渠道、原账号，列表自身不轮询渠道。完成时限量缓存私有封面。
- 安装/升级：先执行配套迁移 282–284，确认后台对账正常，再启用工作台及获准的渠道。回退先关闭新生成，保留能识别钱包记录的版本，待冻结任务、未明回执和对账事项排清；不删除账本或还原生产数据库。
