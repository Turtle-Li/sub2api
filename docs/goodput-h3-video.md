## Contract and scope

The GoodPut Videos API sends both images as `media` entries with `type: first_frame` and `type: last_frame`. The role table and example do not show Fast, so the Fast-specific model card is separate evidence, not a substitute for a real Fast result. An accepted request or returned task ID is not evidence that both images control the final video.

GoodPut's public catalog on 2026-11-19 returned both models at CNY 0.09 per billable second (listed regular price CNY 0.50), and no public Seedance listing. This is an upstream cost, not the Sub2 wallet price. At that rate, 5/10 seconds cost CNY 0.45/0.90, and 400–700 billable seconds cost CNY 36–63 before creative retries. [MiniMax's mainland API price list](https://platform.minimax.cn/docs/pricing/overview) lists H3 at CNY 0.50 per output second at 768P. GoodPut describes its Fast tier as a different compute queue for the same H3 model, not the official Highspeed/Lite tier. The source contract is GoodPut's [Videos API](https://goodputai.cn/zh-CN/docs/video-generation) and [public pricing API](https://goodputai.cn/zh-CN/docs/public-api). The separate Ark [Seedance](seedance-api.md) path, Grok, and native Muse keep their own protocols and accounts. Shared account admission, task ownership and per-second usage follow the Sub2 media path at baseline `5fe2f8486fd36446b2fa4381fbe90f188b571c82` (`backend/internal/handler/grok_media.go`, `backend/internal/service/grok_media.go`, `backend/internal/handler/grok_media_slots_test.go`).

The pilot supports JSON text-to-video, first/last frames and reference URLs/inline data URLs through `media` or `input_reference`. Do not mix frame inputs with `reference_*` inputs. Default duration is 5 seconds. Only Fast accepts `seed`. Binary multipart input is not enabled for the pilot. The adapter does not fetch client-supplied asset URLs; use non-sensitive, publicly reachable references with enough expiry for queue time.

- `POST /v1/videos` returns a `gpv_` task ID after the owner, account and pending usage metadata are recorded. Ambiguous submissions are not replayed and have no fallback.
- `GET /v1/videos/{id}` returns the normalized state. `GET /v1/videos/{id}/content` returns MP4 using the same Sub2 key. The returned `video_url` is a protected Sub2 relative path; it is not a signed provider URL, and still requires the Sub2 key. No GoodPut key, native task ID, or storage URL is sent to the caller. Do not follow provider redirects with a credential.
- Only the creating user, key, group and account can be used for lookup; ownership metadata is retained for 24 hours. Terminal failed tasks do not bill. First observed completion schedules one video usage settlement based on matching `usage.duration_seconds`; repeated poll/download shares the established usage dedup ID. The 720p bucket is a wallet pricing key, not a selected output canvas. The pilot has no background reconciliation or durable task-lifetime balance hold: keep it owner-only and do not use it for customer traffic.
- Before each new submit, the adapter checks the unauthenticated GoodPut catalog for that exact ID, CNY, and a single known seconds meter at or below CNY 0.09. It refuses to submit for a missing/unverifiable price, a new meter, or a higher price. This check is not a locked price from GoodPut. Use a dedicated Key budget, compare the first live bill, and drain tasks before changing Sub2 prices. Existing task reads do not depend on the promotion still being active.

1. For this pilot, reuse the GoodPut account already configured in Sub2; keep its upstream credential inside the existing runtime. No Vault import, new upstream key, or secret extraction is part of this test. Use a low provider spend cap and verify model entitlement and available balance with supported account/model discovery and the provider console.
2. Add an OpenAI **API Key** account with base `https://api.goodputai.cn/v1`. Use only exact identity mappings `minimax/h3` and `minimax/h3-fast` (or one of them). No Ark, Grok or Muse capability and no paid fallback account. When the existing outbound URL allowlist is enabled, review approval for the exact GoodPut API and public catalog hosts separately; do not disable the allowlist.
3. Bind it only to an exclusive OpenAI wallet group. Enable media generation and an explicitly approved positive 720p per-second video price in the wallet's USD-source units (do not copy the CNY upstream rate as if it were USD or add a token price card). Enable the group model allowlist with only the two exact H3 IDs or a subset; use no wildcards. Do not grant it to users or publish in Model Plaza other than the explicitly approved owner pilot.
4. After a separately authorized release, run the first/last-frame acceptance below using a short-lived, owner-only Sub2 test key bound exclusively to the existing group. Reconcile provider and Sub2 usage separately. The admin Grok connectivity test is not an alternative: its video request goes to `/v1/videos/generations` with at most a single `image` and cannot preserve GoodPut’s two frame roles.
5. Ask GoodPut for authorization before resale or opening customer access. For rollback of a pilot, stop new calls via the private key/group and preserve bindings until accepted tasks drain; no schema migration or default configuration is involved.

Local verification uses mocked upstream price, creation, polling, and content replies. No account, payment, deployment, or production configuration is created by these tests. The focused service/handler/route race tests passed with `go test -tags unit -race ./internal/service ./internal/handler ./internal/server/routes -run TestGoodPut -count=1`.
