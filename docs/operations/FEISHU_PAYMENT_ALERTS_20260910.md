## Acceptance
- AC1: Central detects order/refund manual review, DEAD or >10min undelivered business outbox, and currently UNKNOWN/PROCESSING refunds pending since submitted_at/created_at >10min. Sub2 detects full durable refund review fences and paid incomplete >10min using paid_at (never retry-updated updated_at).
- AC2: Each service owns its data and its own incident/delivery tables. No shared product DB credentials or payment-state mutation; preserve organization/product/app/environment isolation and central worker RLS.
- AC3: First occurrence creates one durable OPEN delivery; same incident reminders no more than hourly, with at most one outstanding reminder. Transactions persist incidents and deliveries together. Sending happens outside locks; token CAS, expired leases, failure backoff capped at1hour and no fixed retry exhaustion that silently loses operator notification. At-least-once transport may duplicate after ambiguous success; stable incident ID included.
- AC4: RESOLVED only after an authoritative known resolution. DB errors, candidate paging, DEAD replay toPENDING, refund UNKNOWN toPROCESSING and immutable manual-review fences must not imply recovery. Ordered per-incident delivery; suppress obsolete unsent reminders after resolution. Reopen creates a fresh generation.
- AC5: Bounded/fair discovery and incident recheck, at most4 sends concurrent. Notification outages must not stop payment/fulfillment/refund workers. Sub2 honors active/standby background ownership via independent lifecycle service.
- AC6: Feishu exact HTTPS host/path, no redirect/cookie/proxy credentials,5sec timeout, bounded response, require explicit zero provider code; HTTP200 with nonzero/missing code is failure. Generic redacted errors only. Unsigned webhook is explicitly allowed. No email behavior changes.
- AC7: Config initially server-side; no frontend redesign. Existing merchant/signing credential agents must not be recreated. Proposed separate lightweight bot memory agents reuse existing agent binaries; one bot Vault item, exact ref and isolated public sockets/networks. Root owns credential injection and deployment.
- AC8: Real PostgreSQL concurrency/lease/rollback/fairness/isolation tests, fake HTTP provider/error tests, existing payment regression, independent QA then Review; live nonfinancial notification smoke only after source/artifact gates. Ordinary purchase stays OFF.

## Architecture decision
Read-only independent architecture review approved per-service durable incidents + deliveries, separate from business outbox. Central must add a narrow security-definer same-environment detector for refund facts instead of broad financial table SELECT/DML. Sub2 gets a separate provider/Stop lifecycle instead of adding network stages to expiry worker. Timestamp/event truth and recovery rules above are authoritative. Fixed reference for new bot protocol: Feishu custom-bot usage guide https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot and official-hosted tutorial https://www.feishu.cn/content/7271149634339422210, checked2026-09-10. Adopt HTTPS text webhook, explicit response-code success and unsigned mode requested by owner. No vendor SDK/source is copied.
