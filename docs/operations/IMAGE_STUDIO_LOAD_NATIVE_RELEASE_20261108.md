## 本轮变更

- 模型和作品分别按 Key 的生图权限、历史任务记录查询，取消遍历所有
  Key 的无效请求；目录改为不读取密钥、IP 历史和实时并发的专用查询。
- 单次模型目录复用分组、用户倍率和账号查询；作品与模型独立加载。
  缩略图改为三个并行读取槽，保留取消、有限重试、浏览器 Blob 限额。
- Gemini 按模型、分辨率将图片输出 token 单价换算成单张价格，然后
  继续使用已有倍率。历史任务快照和已结算金额保持原样。
- 复用“一键生图”现有万相、Seedream 凭据，接入账号252和253，各自
  两个模型共用同一账号并发限制。凭据仅在源服务器内存、受保护传输及
  Sub2 现有服务端账号配置中使用，没有新增 Vault 条目或本地明文文件。
- Muse 沿用账号227；正式价格配置在分组27的模型专属价格卡。WorkBuddy
  测试分组40及账号250保持关闭。

继续使用已有生图任务/条目表及账本，历史作品来自这些任务记录，未遍历
历史请求日志。不新建第二套任务或扣费系统。新任务在结果处理时保存
持久化 JPEG；缺少预览的老任务才触发一次受控的服务端补齐。之后列表
直接读云端 JPEG，并使用浏览器私有缓存和有上限的 Blob 缓存。列表不
自动下载原图；打开详情、引用或明确下载才请求原图。

截至验收，分组27只有所有者的1个现有 Key；新账号没有绑定其他分组。

## 验收发现与限制

Seedream Pro 与万相普通版首次任务均在尝试记录存在时遇到存储错误，
最终各失败1项、实际扣费0，原尝试没有再次发起生成。现有旧日志无法
区分尝试记录确认失败与最终结果写入失败，不能断言上游是否已消耗额度。

针对代码中另行复现的“结果保存失败后丢失”缺口，已发布最多3次、间隔
250/500ms的同键条件写入重试；只重试保存当前内存里的结果。取消立即
停止，已存在的结果优先，生成POST及尝试抢占不重试。新增回归在旧实现
失败，修复后通过，包括确认丢失、取消、上限及上游调用次数仍为1。
COS条件写入还补上了状态/错误码/类别的脱敏诊断，不输出响应正文或URL。
此补丁不能恢复先前已经失去的结果，也不能把原失败任务算为通过。

万相 Pro 的持久化原生回执已核对，上游只读状态为SUCCEEDED，收取已有
结果的只读验证能取到1张图片；没有额外发起生成。工作台随后通过已有
回执完成恢复，最终成功1张、入库并结算0.60，持久化预览可读。不能仅凭
这次恢复推断原先等待的精确原因。有关定位与保护的详细证据见
`../bugs/backend/BUG-20261108-native-result-persistence.md`。
