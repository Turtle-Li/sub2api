## Resolution rule

Take an upstream implementation directly when it fixes a defect or is a
semantic superset of the fork. Where both sides changed the same behavior,
preserve the fork's production contract and integrate the independent upstream
improvement. Do not remove fork-only payment/refund, CNY settlement, BPS,
fixed-egress, proxy-pool, exact-N image, async/batch-image, COS, OpenCode relay,
or deployment controls merely because they do not exist upstream.

## Adopted upstream behavior

- Account-statistics and gateway billing apply the upstream long-context price
  gate while retaining the fork's settlement-currency projection, account cost
  basis, key quota cost, and exact-N image accounting.
- Free/Fast requests without catalog pricing still write a zero-cost usage row.
- A nil channel image price inherits catalog pricing; an explicitly configured
  zero remains free.
- Risk-control user allowlists are log-only and do not block or trigger the
  normal rejection side effects.
- Composite routing can forward WebSocket traffic to Grok, subject to the
  fork's existing Grok endpoint, DNS, redirect, and private-host policy.
- CC Switch imports use the provider root URL and derive exactly one
  `/v1/usage` endpoint, avoiding `/v1/v1/usage`.
- Claude-only group behavior, Claude reset-credit status, model-catalog fixes,
  stream usage forwarding, and the upstream model-whitelist mapping fix are
  retained.
- Redis Compose commands use the upstream exec-list form. Production must keep
  `REDIS_USERNAME` empty unless matching Redis ACL configuration is also
  installed; `--requirepass` alone does not create a named ACL user.

## Union resolutions

### Billing and pricing

The conflict points are
`backend/internal/service/account_stats_pricing.go`,
`gateway_usage_billing.go`, and `openai_gateway_usage.go`. The merged path uses
upstream long-context selection and zero-cost fallback together with the fork's
`referenceModelCost`, resolved-price state, USD account-quota basis, settlement
currency, quota debit, and image-count rules. Model-price changes must retain
tests for both the reference-price calculation and wallet denomination.

### Risk control and audit evidence

The conflict points are
`backend/internal/handler/openai_gateway_handler.go`,
`backend/internal/service/content_moderation.go`, and the content-moderation
repository tests. Allowlisted flagged requests continue, but their moderation
logs retain the fork's `FullPrompt` evidence. The log-only path must not create
normal rejection side effects, and the non-allowlisted path remains fail
closed. This is covered by `risk_control_allowlist_test.go` and the repository
detail/count tests.

### Composite Grok routing

Upstream's composite-to-Grok behavior is accepted. Production SSRF protection
is not weakened: tests opt into the private test server with
`AllowPrivateHosts` plus an exact upstream authority. The handler still closes
the selected-account lifecycle and never forwards after an earlier failure.

### CC Switch and client defaults

Upstream URL normalization and the fork's WebSocket settings are combined in
`frontend/src/utils/ccswitchImport.ts`. Usage scripts derive the active key's
settlement currency. The fork deliberately keeps `gpt-5.6-terra` as the OpenAI
default instead of upstream's older `gpt-5.5` default.

### Dashboard settlement currency

The upstream spending trend exposed a pre-existing hard-coded dollar sign in
the admin dashboard. The merged dashboard reads public `pricing_currency` and
uses the active settlement symbol for summary cards, axes, and tooltips. Locale
labels are currency-neutral. This prevents CNY deployments from presenting
wallet-denominated amounts as USD.

### Generated dependency wiring

`backend/internal/handler/wire.go` contains both upstream's new Claude reset
handler and the fork's proxy-pool handler. `backend/cmd/server/wire_gen.go` is
regenerated from that provider set rather than manually merged.

## Deliberate fork differences

- Unified payment, provider identity in Vault, signed webhooks, refunds,
  coupons, invoices, reset cards, immutable benefit snapshots, and CNY wallet
  accounting remain authoritative.
- Image 2K/4K requested-tier billing, real-pixel validation, exactly-N repair,
  asynchronous delivery, batch isolation, shared limiting, deadlines, and COS
  write fences remain authoritative.
- BPS continuation/fallback/cooldown/breaker behavior remains authoritative.
- Fixed OAuth egress, Tailnet role isolation, proxy binding CAS, probe snapshot
  invalidation, Grok relay validation, and proxy pools remain authoritative.
- OpenCode Go eligibility remains the union documented in
  `UPSTREAM_V028_20260923.md`, including relay/upstream accounts and the mirrored
  service/SQL predicate.
- Upstream's Antigravity pre-content keepalive is deliberately not adopted.
  Sending an SSE comment commits HTTP 200 and prevents the fork's established
  account failover for signature-only, malformed-function, empty, timeout, and
  read-error streams. Normal keepalives still begin after meaningful content;
  until then the response remains uncommitted so the handler can retry another
  account.
- Releases remain manual-dispatch, exact-revision, maintenance-lock protected,
  blue-green deployments with drain and runtime-guard recovery.

## Production disposition

The merged application plus the ingress-contract repair was released as exact
OCI revision `6b8a1aab879002bd4057080f69b7b1288e36a0c4`. GitHub Actions run
`36640878475` completed the image build and healthy green-slot cutover, then
stopped before Caddy mutation on the generated source-identity mismatch
documented in
`docs/bugs/deployment/BUG-20260930-aws-request-body-limit-drift.md`. After the
receiver fix passed independent review and its production three-view check,
the unchanged `6b8a1aab` Caddy template was activated through the canonical
transactional receiver. The final 17 MiB/128 MiB boundary probes, active image
revision, environment, Caddy views, health, lock, and transaction checks all
passed.

Repository `main` later advanced through independent commit `6703c64952c6b4e96f687a84f9e458d164f7de6d`
for multi-provider batch images and receiver-only fix
`369c21efa4afb11758552b650adf5e5c225ee942`. The batch-image task explicitly
left production deployment on hold pending owner-authorized migration of the
existing COS credential into the shared Vault agent. Those later application
changes were not bootstrapped or deployed as part of this upstream merge, so
production must not be described as running current `main` until that separate
Vault gate is completed.
