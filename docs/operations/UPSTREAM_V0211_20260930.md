## Resolution rule

Adopt upstream behavior when it fixes a defect or is a semantic superset of the
fork. Where both sides changed the same path, preserve the fork's production
contract and integrate the independent upstream improvement. In particular,
do not replace the fork's payment/refund, CNY settlement, BPS, fixed-egress,
proxy-pool, exact-N image, batch-image/COS, OpenCode relay, or deployment
controls merely because upstream implements a simpler path.

## Adopted upstream behavior

- Redis-backed in-flight wallet reservations prevent concurrent requests from
  spending the same available balance. Reservations are released after final
  billing and degrade safely when Redis is unavailable.
- Claude Code-only groups can use configured OpenAI-compatible fallback groups
  without weakening the fork's existing group and account selection rules.
- Claude reset-credit redemption now has idempotency and distributed-lock
  protection.
- GPT-6.1 Sol, GPT-6.1 Astra Ultrafast, and their plan/model metadata are
  available through the existing model and pricing paths.
- Codex model discovery prefers the upstream remote catalog, enforces a 1 MiB
  response limit, and falls back to the packaged local catalog.
- API-key creation applies an active-key ceiling and an hourly Redis-backed
  creation limit. The default hourly limit is 60.

No database schema migration or dependency-lock change is introduced by this
release.

## Conflict resolutions

### Billing and wallet denomination

The upstream reservation estimate described its result as USD, but the fork's
wallet is settlement-currency denominated. Applying the upstream code directly
would under-reserve non-OpenAI costs in CNY and could double-convert some
standard OpenAI media/search prices. The merged implementation normalizes raw
USD estimates through the fork's authoritative settlement policy and treats
already-settled BillingService breakdowns separately. Tests cover CNY
non-OpenAI token costs, standard OpenAI reference-dollar behavior, and media or
search paths that must not apply foreign exchange twice.

Independent review also found that upstream's max_reservation_usd cap was
being compared after conversion to wallet units. The merged estimator converts
the USD-authored cap through the same settlement policy before applying it, so
1 USD cannot silently become 1 CNY in a CNY deployment.

The upstream WebSocket integration reserved only the first response.create
frame even though one connection can carry many billable turns. The merged
handler maintains a separate reservation per turn, performs admission before
each later frame is written upstream, and hands that exact reservation to the
matching asynchronous usage task. Error/cyber billing paths retain the same
reservation until their billing work completes. Each real first-frame attempt
is also reserved independently, including a safe replay after handler-level
account failover; a failed attempt cannot release the logical turn and leave
the replacement account's replay unreserved.

The fork's GPT-6 Sol/Luna custom multipliers and component pricing remain
authoritative. GPT-6.1 Sol is added with the upstream official 1x multiplier.

### Configuration and dependency wiring

The billing configuration keeps the fork's
`currency_cutover_cache_bypass_file` and adds upstream
`inflight_reservation` controls. API-key limit defaults are included. The
generated server injector contains upstream Claude redemption idempotency and
leader-lock providers together with all fork-only providers; `wire_gen.go`
is regenerated from the combined provider set.

### Codex catalog and client diagnostics

The frontend keeps the fork's typed network, HTTP, manifest, and CORS
diagnostics and its `gpt-5.6-terra` default. It adopts upstream client version
`0.158.0`, remote/file catalog mode, response-byte accounting, and the 1 MiB
catalog limit. The user-facing key modal retains the fork's browser-specific
error guidance while exposing the upstream catalog source behavior.

### Stable localized error contracts

The insufficient-balance test asserts the stable machine code
`INSUFFICIENT_BALANCE` rather than upstream's hard-coded English word
`balance`. This preserves the fork's localized Chinese message without
weakening the API error contract.

## Residual risk

The active-key ceiling currently follows upstream's repository count followed
by create operation. Two concurrent creates can both observe the same count and
transiently exceed the configured ceiling. The hourly Redis limiter is atomic,
but the database-backed active count is not. This is a bounded P2 concurrency
risk and should be corrected with a transaction/advisory-lock or equivalent
atomic persistence contract before treating the active ceiling as a hard
security boundary.
