## Release-blocking image decoder dependency

ANALYSIS_READY: GitHub Security Scan run `37914722408` reports three reachable
vulnerabilities in `golang.org/x/image v0.41.0`: GO-2026-6222 (crafted VP8L
memory exhaustion, fixed in v0.45.0), GO-2026-5061 (WebP dimension mismatch
panic, fixed in v0.43.0), and GO-2026-4961 (large WebP panic on 32-bit, fixed
in v0.42.0). Reachability is through `decodeUpscaleImageConfig` →
`image.DecodeConfig` and `compressInlineAvatar` → `image.Decode`; it is not a
scanner infrastructure failure. The official Go vulnerability database
confirms the affected decoder symbols and fixes:
https://pkg.go.dev/vuln/GO-2026-6222 and
https://pkg.go.dev/vuln/GO-2026-5061.

Repair scope: pin only this module to v0.45.0, inspect its fixed decoder source
and regression tests, preserve application limits/API behavior, run decoder
and application image/avatar regressions, and re-run CI/security on the final
commit. Do not waive the scanner or deploy the vulnerable merge commit.

The v0.45.0 source review confirmed WebP canvas/frame dimension checks and
bounded/remapped VP8L Huffman groups; its `webp/decode_test.go` exercises the
large-Huffman-index rejection. Upstream WebP tests and project avatar/upscale
unit regressions passed. Local `govulncheck v1.8.0 ./...` exited zero with no
reachable vulnerabilities (two uncalled module-level advisories remain
informational). Existing x/sys and x/text selections already satisfy v0.45.0;
no other dependency version changes are required.
Dependency reference: https://go.googlesource.com/image at
`refs/tags/v0.45.0`; adopted decoder behavior is in `webp/decode.go` and
`vp8l/decode.go`, with regressions in `webp/decode_test.go`. The BSD-3-Clause
license/notices remain applicable; no decoder code is copied into this fork.
