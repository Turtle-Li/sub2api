## Integration decisions

- Preserve local internal-credit billing, hidden consumption multipliers,
  configured model prices and the GPT-6.1 Sol subscription long-context rule.
- Keep fail-closed `ResolveAccountProxyURL` in Antigravity discovery while
  adopting upstream catalog metadata and the expanded return signature.
- Keep the verified-probe catalogue gate alongside upstream's intentional
  empty OpenAI catalogue after retirement filtering.
- Retain local currency-cutover configuration tests and upstream minimum-output
  configuration tests.
- Stripe credentials come from the matching local recovery snapshot. Retain
  the local requirement to wait for COMPLETED fulfillment after PAID.
- Retain collection, reset-card, unified-payment and reviewed-refund admission,
  entitlement leases and manual-review boundaries. Unknown order types adopt
  upstream's failed-fulfillment audit instead of becoming balance credits.
- Pending refunds retain the upstream deduction hold until gateway settlement.
  Failure restoration and its audit are atomic and idempotent. Preserve local
  settled/requested amount separation, persisted converted gateway amounts,
  explicit no-deduction choices (including legacy `deduct_balance`), and
  numbered `REFUND_PENDING` audit lookup.
- Alipay stores the refund request number and supports both upstream order
  references and local durable `sub2-cancel-<id>` references during queries.
  Payment notification confirmation uses the exact verifying provider instance.
- Account-test discovery skips retired OAuth GPT-5.5 and prefers the live
  GPT-5.6 Terra model. The regression fixture deliberately includes both.
- Stale local fixtures adapted to upstream rules (tests only): ModelTrace's
  scheduled-deadline case probes `gpt-5.6-sol` instead of retired GPT-5.5, and
  the PostgreSQL paid-first cancellation case expects the unknown-type order to
  keep its trusted paid claim and then become FAILED with
  `unsupported order type: test_only`.
- Review fixes: the pending-refund audit always serializes
  `deductionRollbackOK` (an explicit `false` while the deduction is held), the
  existing-order Stripe route no longer carries `client_secret`, and the Stripe
  page selects its recovery snapshot by the requested order ID.

## Rollback fence

A pre-v0.2.17 binary reads `REFUND_PENDING` audits with the old
deduction-restored-on-pending semantics. Before rolling back to such a binary,
settle (or record for manual review) every non-unified `REFUND_PENDING` order
created by v0.2.17. Its held deduction must not be finalized or retried by an
old binary.
