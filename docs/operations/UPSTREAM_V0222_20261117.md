## Merge contracts

- Persist and price OpenAI 30-minute and 12-hour cache writes separately.
  Ordinary, batch and transaction writes retain the fork's settlement currency,
  paid fallback marker, response model attribution and video fields. Pricing
  rows and intervals retain currency and operator-defined flat price semantics.
  Account-side usage costs remain separate from amounts charged to customers.
- Keep the fork's account reserve admission, fixed proxy egress and upstream
  model attribution. Adopt upstream's bounded reading, stream termination and
  drain changes. Antigravity waits for content before committing the response;
  failure before the first content remains eligible for failover.
- Keep exact image counts and the fork's direct image and Muse settlement
  paths. Native-only Codex image models may not fall back to Responses when the
  Images endpoint is unavailable. Alipay uses a supplied durable refund
  reference when present.
- Keep CC Switch's normalized import endpoint, embedded WebSocket settings and
  local `gpt-5.6-terra` default. API-key copy in the key dialog still supports
  native image extension auth.
- Auth cache version 29 invalidates entries with either parent layout.
  MCP is off by default; the new per-group UltraFast switch defaults to false.

## Database and AWS release

All five new migrations retain upstream file names and content. The runner
identifies migrations by full file name; the existing fork migrations sharing
a numeric prefix stay in place.

- `249_add_usage_logs_api_key_cost_index_notx.sql` builds the usage index
  concurrently.
- `249_mcp_oauth.sql` adds MCP grant, code and credential tables.
- `250_openai_cache_write_ttl.sql` adds usage and pricing columns.
- `251_group_force_openai_ultrafast.sql` adds the opt-in group flag.
- `251_group_usage_rollup_nonblocking_build.sql` adds rollup state and updates
  invalidation functions to support rebuilding alongside usage writes.

The AWS application uses the existing GitHub-built, verified image receiver and
blue-green release. The Caddy template is unchanged. Dispatch with
`deploy_caddy=false` so the independently managed API proxy route stays live
through the slot switch.
The separate Caddy template publisher assumes a single backend across the
shared site; on the current topology it diagnoses ambiguity after the
application deploy. See `deploy/API_PROXY_INGRESS_20261108.md`.
