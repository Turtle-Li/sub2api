## Continuous edit handoff

`useEditContinuation.ts` is a host adapter, not upstream source. Each edit submit
records the returned job ID and current selection version. A terminal successful
job with a successful item and at least one image advances the default reference
to output index 0 exactly once, updates source metadata to that item, and preserves
the persisted root batch ID and any next prompt already being typed.
Manual output selection, model changes, reference removal/upload, leaving the
thread, a newer submit, and session/key abort invalidate the previous generation.
The version is checked again after image download. Failures, partial failures,
missing images and download failures retain the existing reference.
Mounted state and two-submission journey evidence:
`.omo/evidence/image-studio/edit-continuation/README.md`.

## Terminal batch projection

`api.ts/taskDisplay` preserves explicit item success/failure. Only unfinished
items inherit cancelled, failed or output-deleted display state from their batch;
completed batches never promote failed/pending items to success. Public batch
`error.message` is shown when a failed-batch projection has no item error.
`BatchImagePublicService.Cancel` may transition only the job (the item remains
pending), so cancellation applies the returned authoritative batch to every loaded
item and continuation immediately. A read version fences older in-flight list/poll
responses; terminal jobs then leave the poll set. No server item status is mutated.
Regression evidence: `.omo/evidence/image-studio/terminal-status/README.md`.

## Server-owned generation parameters

InputBar's size/aspect controls are a host adapter inside the creation rail. The optional
`BatchImageModel.capabilities` contract is exactly `image_sizes`, `aspect_ratios`,
`default_image_size`, `default_aspect_ratio`, `max_reference_images`, and
`response_mime_types`; no frontend provider/model capability table exists.
Valid selections survive model updates; invalid selections use the advertised
default when valid, otherwise the first advertised option. A user change remounts
the workspace and clears selections/references. The first advertised response MIME
is used only when present. Models without capabilities omit all three parameters.
Reference overflow blocks uploads and submission, while existing images remain
removable after model changes. Dimensions are generation targets; the actual file
is authoritative. Serialized parameters participate in the existing stable
idempotency body identity. Capability fixtures and regression evidence live at
`.omo/evidence/image-studio/model-parameters/`.

## Current host design and routing

`studio.css` provides scoped semantic light/dark surfaces, text, border and teal
accent tokens and named rail/card geometry. It retains upstream Tailwind scales
and measured virtualization. The host adapter changes card geometry to image
above metadata, with a fixed measured height; the underlying task states, lazy
image loading, actions, viewer and gesture implementations remain adopted code.
The existing AppLayout supplies the only page header. Desktop uses a 320px rail;
phone uses the same controlled form in a native modal with a sticky submit action.
Literal CSS breakpoints remain necessary; they cannot use custom properties.

`workspaceAPI.ts` aggregates capability catalogues with at most six concurrent
directory reads. It deduplicates exact provider/model identities and exposes no
key/group selector. Routing uses the first eligible owned key in stable ID order,
or the original task key for a continuation. Histories retain independent key
cursors and authenticated asset/cancel ownership. An uncertain submission stays
bound to its original key and idempotency ID even after catalogue refresh. There
is no automatic POST replay, failover, hidden credential or second task authority.
If a model change requires another key, the reference remains but a new work is
explicitly started because persisted roots are key-owned. Single/batch modes are
explicit; only batch mode splits prompts on a standalone `---` line.

The old guide component and navigation entry are removed. `/batch-image` and
`/docs/batch-image` redirect to `/image-studio`; the backend batch API is retained.
Current redesign and acceptance: `docs/features/IMAGE_STUDIO_REDESIGN_20261108.md`.

## Catalogue and gallery refinement (2026-11-08)

The owner also maps platform/model selection and gallery delivery to VSO
`4edef85ab3716fd43989b4a49561a148ba500d93`. Inspected its `workspace.js`
platform/price UI, `GalleryCardQueryService` and its paging/cursor tests,
`GalleryCardAssetService` and its owner/variant tests, and `ImagePreviewService`
480px JPEG quality80 variant. Source/test paths and intentional differences are
recorded in `docs/features/IMAGE_STUDIO_GALLERY_OPTIMIZATION_20261108.md`.
No VSO source is transplanted; this host uses existing batch job/item rows,
authenticated cached thumbnails and standard credit units. VSO projection
tables, direct object capabilities, signed snapshot cursors and its wallet are
not adopted. The upstream 88lin MIT license and executed virtualization,
viewport gating, gestures and viewer modules remain retained.

`ModelPicker.tsx` is a host-owned searchable native dialog with platform families,
exact model IDs and size-sensitive backend quotes. Routing remains the first
eligible key, including that key's quote; account differences appear as a range.
History and catalogue now resolve independently. The host `api.ts` reads 24
joined item/job records per key/page; root/status/search filters run on the server.
`TaskCard` uses `thumbnail()`; original detail/edit/download uses `image()`.
No task state moves to browser storage. Originals retain their download queue;
thumbnail reads use an independent queue and each card cancels when offscreen.
Server-side historical backfills retain the per-user download permit. A completed
job transition and explicit metadata refresh reload its cover, including a previous
temporary failure; unchanged records do not repeat reads. DOM rendering remains
measured and virtualized.

The persistent-variant contract is also mapped to pinned VSO
`service/ImageVariantStorageService.java` and
`service/ImageVariantStorageServiceTest.java`: eager stored variants avoid
original reads, and historical backfill is persisted and reused. Verified at
`4edef85ab3716fd43989b4a49561a148ba500d93`; the Sub2 adapter now stores
versioned JPEG objects in the existing private delivery store. New
inline/upscaled results capture previews eagerly; historical successful items
backfill by batch behind a renewable shared lease. Memory is only an accelerator.
Server ownership, retention and deletion gates precede cache/ETag responses;
originals stay explicit. No VSO source was copied. Implementation, matching tests,
storage requirements and archive-only differences are recorded in
`docs/features/IMAGE_STUDIO_PERSISTENT_THUMBNAILS_20261108.md`.
